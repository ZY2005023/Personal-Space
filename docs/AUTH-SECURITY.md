# 管理员安全与初始化准备

2026-11-03 · N6代码准备，不代表已初始化或可上线。

## 使用边界

站点只允许一个管理员，没有注册API、默认账号或认证绕过。登录仍由Auth.js Credentials提供方负责，要求密码以及TOTP或尚未使用的恢复码。业务接口与8项安全扩展使用同一会话。安全界面位于/admin/security，接口契约在contracts/auth-security.yaml；该文件不重新定义Auth.js原有登录/退出端点。

本轮没有真实数据库或管理员，安全页仅通过构建与匿名跳转检查，不能实际登录操作。

## 初始化（本轮仅运行无参数帮助）

先在另行授权的隔离环境完成PostgreSQL18模型、物理约束、最小权限和备份；不要直接db push。再配置DATABASE_URL、至少32字节的AUTH_SECRET、独立的32字节base64 TOTP_ENCRYPTION_KEY和正确AUTH_URL，不把任何真实密钥提交或贴到聊天。

`npm run admin:init`默认只显示准备说明。只有用户之后明确授权创建账号，才在本机交互终端执行`npm run admin:init -- --create`。该模式拒绝密码参数、输入重定向及非交互终端，还要求再次输入CREATE ADMIN确认。

脚本要求3至64位ASCII用户名和15至128个Unicode码点的密码，不裁剪密码空格。输入密码和验证码时隐藏回显；验证器密钥需要在本机终端显示一次供手动绑定。确认实际TOTP后才在同一事务里创建唯一管理员、10枚恢复码哈希和审计；已有任意管理员则拒绝初始化。它不创建数据库或执行迁移。

成功后恢复码明文只在当前终端展示，请离线保存。初始化确认使用过的TOTP不能用于登录，需要等下一组。脚本不会自动保存密码、密钥或恢复码文件；终端录屏/滚动记录仍由实际操作环境负责保护。真实终端隐藏输入、Windows/Linux、异常中断和并发初始化尚待验证。

## 安全页面

修改密码、重置恢复码、更换验证器及显式撤销会话，每次都重新验证当前密码和第二因素。刚用于登录或重新认证的验证码不能重放。没有验证器时，可用一枚未使用恢复码；验证器与全部恢复码都丢失时，没有网页登录绕过通道，需后续离线身份核验和灾难恢复流程。

再次验证生成5分钟有效的随机证明，数据库只保存SHA256摘要，并绑定管理员、当前会话证明摘要、会话版本与具体操作。证明只能消费一次，不是新的登录会话。Origin和CSRF也必须通过。

更换验证器分两步：先取10分钟有效的待绑定凭证和新密钥；此时原验证器保持有效。核对新验证码后才原子替换验证器、恢复码并撤销旧会话。取消时服务端立即消费待绑定凭证并清空待绑定密钥。到期或会话不符均拒绝使用。

密码、验证器、恢复码更换及显式撤销会话都会增加session_version，包括当前浏览器在内的旧JWT后续请求失效。普通退出也按单管理员策略撤销对应版本的所有会话，界面写明“退出全部设备”；旧版本退出不能再撤销新版本。数据库故障时的真实退出语义尚待验证，不能仅凭前端跳转断言撤销成功。

恢复码重置或更换验证器成功后，新明文只保留在当前页面内存，不保存到localStorage、sessionStorage、日志或审计。刷新/离开后不能取回；若网络丢失成功响应，需要用验证器重新登录、再次认证并轮换另一组。不能靠旧证明重复取回新恢复码。

## 存储与维护

密码/恢复码使用Argon2id（19MiB、2轮、并行1）。每枚恢复码有128位随机熵并独立加盐。TOTP为SHA1、6位、30秒，最多前后一步，消费步骤由数据库条件更新保护。参数依据见[OWASP认证](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)及[多因素指南](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html)；参数不替代真实服务器资源与延迟测试。

正式与待绑定TOTP分别采用带版本和purpose AAD的AES-256-GCM封装。数据库只有密文，消费或撤销待绑定记录时清空待绑定值。旧代码三段式密文不会自动接受；没有既存真实账号，本轮无数据转换。

SecurityChallenge是新增的实现模型，当前总模型30。只有Prisma模型和应用事务，尚未建表或实施全部CHECK/角色权限。过期记录的维护清理尚未接上；过期记录即使仍保留，也不能通过消费查询。机器与数据库时钟同步、密钥独立备份及轮换均需在真实环境验证。

## 已检查与仍待验证

104项单元/内存替身测试通过，包含错误密码、TOTP重放、恢复码一次消费、独立限流、并发前版本变化、证明过期/用途/会话隔离、改密与初始化回滚、MFA确认/取消及旧退出令牌。39项本机只读HTTP检查含安全页跳转与8项匿名操作拒绝。没有真实成功登录、跨设备JWT重放、真实SQL锁/回滚、终端绑定或浏览器安全操作证据；这些仍属于IV-01/02/05/06/08。

N6已补最后一枚恢复码登录后的换绑代码：成功恢复码登录会在同一事务里记录RECOVERY_LOGIN证据，并绑定即将签发的Auth.js会话nonce。登录后自动进入安全页面的更换验证器入口，5分钟内再次输入当前密码即可开始，不再要求另一枚恢复码。

此确认只允许MFA_REPLACE，不可直接修改密码或领取恢复码。核对新验证器后才替换原验证器、轮换恢复码并撤销旧会话。普通验证码登录、其他浏览器、过期、旧会话均不能使用此入口。页面上的recovery查询参数只控制显示，不授予权限。

开始请求丢失响应时，同一会话再次输入密码可在原5分钟内取回同一待绑定密钥；重试不再生成密钥或延期。确认完成或取消后不能重用。取消会立即作废待绑定密钥，界面会提示没有其他因素时将无法继续在线恢复。整个恢复换绑窗口以恢复登录时的原5分钟为限，操作时应及时完成。

这些流程只有内存替身与匿名检查，没有真实登录或数据库故障证明。窗口过期、主动取消、恢复登录提交成功但浏览器未收到会话、或全部因素丢失时，仍需其他未用恢复码/原验证器或后续离线核验流程，不能临时开放网页绕过。
