# N7：后台内容与历史分页

2026-11-03 · 代码准备；没有创建数据库、账号、迁移、存储或部署。

## 本轮行为

后台内容及回收站列表默认20、上限100，SQL使用limit+1判断后页，只返回契约中的AdminSummary。标题关键词、模块、类型和删除范围在服务端筛选；API还实现已有分类/标签参数，匹配工作草稿引用，不误用线上投影。页面提供关键词/模块/类型表单、清除、下一页及返回第一页，筛选时回到第一页。

排序键为最近状态或草稿保存时间与ID，不改变state_version。状态时间列保留真正的状态更新时间。签名游标绑定管理员、全部筛选及回收站范围；切换筛选或复用其他内容/管理员游标返回400。重复或非法参数、超过100字及空字符关键词均拒绝，SQL通配符按字面转义。

编辑器只读一个内容的当前草稿和状态，不再读取全部历史/路由；状态端点只读状态，不加载草稿。单个历史版本通过contentId+revisionId+管理员直接查1条。历史分页默认10、上限100，按不可变版本号排序，创建时间不单调也不作为边界。弹窗显示加载、失败重试及较早版本入口，关闭后忽略迟到请求，避免覆盖重新打开的结果。

概览不再include全部内容聚合：SQL统计公开数量、待发布更改及相册，最近编辑只读5项。公开计数要求有效正式版本；待发布比较完整可编辑payload（排除服务端taxonomySnapshot副本），正文/图片/设置变动不会因标题相同而漏计。写操作、版本、权限、恢复默认私密等规则不改。

## 尚待验证与限制

查询测试是替身，不执行SQL，也不证明数据库归属条件、索引或隔离已生效。需要隔离PostgreSQL18/UTF8下执行normalize/ILIKE、NULL、时间精度、同时间ID边界、实际关系过滤、并发保存/移入回收站、游标翻页、权限/错误码及2秒查询预算验证。执行计划、跨表活动时间排序和标题表达式索引需另行设计，不能仅凭LIMIT宣称数据库只扫描一页。

实时列表排序键会随编辑改变；并发修改可能把未读条目移动到第一页，需刷新，不承诺跨请求冻结快照。历史不可变，新增版本在重新打开列表后显示。

历史页仍按现有契约携带完整payload，单篇大正文与100条上限的响应内存仍需IV-08评估。发布/恢复等写事务内部仍读取完整历史聚合，本轮没有优化这条路径。公开分类目录分页、Outbox消费/GC、导出备份及高级物理约束继续待实现。
