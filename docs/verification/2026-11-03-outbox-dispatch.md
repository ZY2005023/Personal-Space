# N10：Outbox到媒体清理任务的可靠交接

2026-11-03。仅实现源码、替身测试及使用说明，没有执行真实Worker处理模式，没有创建数据库、迁移、账号、对象存储或部署。

## 本批行为

新worker:outbox入口每轮认领一条MEDIA_DELETED事件，按创建时间/ID排序，FOR UPDATE SKIP LOCKED跳过占用行；仅处理到期PENDING或租约过期RUNNING。数据库时钟设置1分钟租约，独立UUID令牌与递增attempts。短事务内重新检查令牌/未过期租约并锁住事件，将任务插入和PROCESSED状态一同提交。

任务ID固定为事件ID；任务类型MEDIA_GC，payload只含mediaId/sourceEventId。严格验证事件字段和aggregateId一致，拒绝事件自带任意对象路径。已有同ID同类型同payload任务只做确认，不重置其状态；其他碰撞永久失败，不覆盖任务。不同事件仍可产生不同任务，未来GC执行器也必须幂等。

临时故障回滚交接事务，再用同租约记录重试，30秒指数退避、封顶300秒，最多5次；永久错误直接FAILED。丢失租约的进程不能插入任务、确认事件或改重试状态。数据库不可用而无法记录失败时进程报通用错误停止，租约到期后允许未来接管。没有在日志输出payload、密钥或连接串。当前模型没有Outbox错误摘要字段，FAILED排查与运维重放仍需后续维护流程。

只实现MEDIA_DELETED处理器，未知事件及CONTENT_STATE_CHANGED保持原状，不会被错误标为成功，也不会阻塞本处理器认领媒体事件。当前公开读取本就每次检查内容状态，没有新增依赖异步事件的权限缓存。

MEDIA_GC只是持久化待办，不是删除授权或完成状态。现有媒体Worker只认领MEDIA_PROCESS，不会处理它。物理删除执行器、宽限期、三层引用复查、备份保护租约和对象孤儿扫描仍未实现；未虚构冻结设计缺失的保留时长。

同时修正现有媒体Worker的顶层await与CommonJS运行配置冲突；两个Worker入口均改为异步main，支持--help及拒绝未知参数。帮助/非法参数分支在读取环境和打开客户端前退出。Outbox等待支持退出信号中断，已有事务先完成再断开客户端。

## 验证及限制

全量144项测试通过（新增9项），覆盖SQL认领边界、事务交接、相同任务重放、畸形载荷、ID碰撞、失败回滚/五次重试、租约丢失、未知事件/空队列及两个CLI帮助/非法参数启动。类型检查、生产构建及契约结构/引用检查通过；依赖和30模型不变，工作契约1.0.2不变。HTTP入口未改，N9的52项HTTP及认证拒绝证据沿用，本批不声称重跑。

事务替身提供回滚行为，但没有运行真实SQL、证明SKIP LOCKED/并发租约或数据库断连恢复。接库后仍需执行IV-02/06，包括多进程认领、租约回收、提交结果不明重试、异常事件人工处理和积压观测。GC与备份保护必须完成且通过IV-07/08后另行验收。
