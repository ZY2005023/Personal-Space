# N8：写事务精简历史读取

2026-11-03 · 没有创建数据库、真实账号、迁移、存储或部署。

## 结果

原mutate会include全部历史payload和所有路由，再在内存计算最高编号。现在内容和草稿行锁之后，按操作加载必要上下文：

- 保存、访问状态/回收站操作：当前内容和草稿，不读历史及路由。
- 手动快照、发布：当前草稿和两个独立最高编号；各findFirst只选择数字字段，不取旧快照payload。
- 历史恢复：只读指定contentId+revisionId所属快照，不读取全部历史或计算新编号。
- 发布地址：只取CANONICAL记录，最多2项用于异常检测；只锁/校验/更新新旧主地址。200条历史别名的替身用例中，旧别名保留，不逐一读写。

内部稀疏上下文有明确标记。编号未加载时禁止创建新版本，不能把未知当作0；已加载最高编号仍与本次新建快照取最大值。手动快照和正式发布保持独立编号，草稿和线上版本ETag不混用。内部元数据不进入外部DTO或JSON快照。

事务边界、内容归属、只追加历史、三层引用、路径冲突、搜索投影、审计、请求重放与恢复默认私密保留。缺失/不合法最高号、重复主地址及不兼容恢复快照会拒绝；转私密不再因为无关旧快照解析失败而被阻止。
